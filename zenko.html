Zenko

Zenko is the repository-side storage and hosting system for the Zenko Android ecosystem. Its job is to hold and serve the resources the Android application needs — including files, root shells and APK payloads — so those resources do not all have to be bundled into the application itself.

View Zenko on GitHub

What Zenko is

Think of Zenko as the remote resource layer behind the Android app. The repository is a place where the ecosystem's downloadable components are organized and hosted. The Android side can then fetch the appropriate resource when it needs it.

Network Teleport

Network Teleport is the name for the resource-delivery concept in the Zenko ecosystem: moving a resource from the remote Zenko host to the Android device over the network when the client needs it.

Why it exists

It keeps the resource side separate from the application. Resources can live on the host and be fetched when required instead of making the app carry every component internally.

What can move

Depending on the workflow, the hosted resource can be a normal file, shell component or APK payload.

Where it ends

The destination is the Android device running the Zenko ecosystem, with rooted-device workflows allowing components that require elevated system access.

What is documented

The current repository does not expose a file explicitly documenting the Network Teleport wire protocol, so packet formats, endpoints and authentication details are intentionally not invented here.

The repository confirms this is not simply an image/file bucket: it contains kernel/module and driver-oriented resources as well as shell/configuration components. The exact role of each binary should be determined from its own implementation or documentation.

Root shell workflow

One of the visible shell components is wrapper_multipurpose.sh. It is a rooted-Android shell wrapper that resolves a requested script from locations under /data/local/tmp, makes the selected file executable, optionally resolves a configuration file, and then executes the selected component.

The wrapper also exposes a configuration path and optional answer/input file. This is a description of the existing repository component, not a recommendation to use it on systems you do not own or have permission to test.

Kernel configuration

The repository's tb_config.txt defines a menu of kernel/driver options and two execution modes. The visible options include entries such as QX1, GT, rt-dev, rt-proc, QX(2), TB KPM, Tear Driver, Bing VIP Driver, Paradise and Ldg KPM Driver. The configuration also labels Background Daemon as not recommended and Foreground Standard as recommended.

Zenko and the Android side

The important distinction is simple: Zenko is the host/storage side. The Android application is the client that consumes the resources. That separation makes it possible to update hosted resources independently of the application's bundled assets.
